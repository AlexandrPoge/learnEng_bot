# Облачный Telegram-бот

Cloudflare Worker принимает Telegram webhook. SQLite-backed Durable Object последовательно обрабатывает сообщения и хранит учеников, попытки, назначения, редактор и очередь доставки. Отдельный сервер БД не нужен. Используются возможности Workers Free; платный тариф не подключается автоматически.

## Подготовка

Нужен Node.js 22+. Локальная версия продолжает работать до переключения.

1. `npm ci`, `npm run check`, `npm run build`, `npm test`.
2. `npm run cloud:check` — сборка без публикации.
3. `npm run cloud:test` — настоящий локальный Workers/SQLite runtime с подменой только Telegram API. Проверяются 30 одновременных учеников, дубликаты, перезапуск и PNG.
4. `wrangler login` — официальный OAuth с чтением аккаунта и правами Workers/scripts/routes.
5. `npm run cloud:deploy` — публикация. До импорта и активации webhook не обрабатывается.
6. `npm run cloud:control -- secrets` создаёт `.cloud-secrets.json` с правами 0600 вне Git. Передача `wrangler secret bulk .cloud-secrets.json` требует разрешения владельца на передачу Telegram-токена, Telegram ID ролей и ключей администрирования в Cloudflare. Значения не выводятся.

## Перенос

1. Проверьте `/health` и `npm run cloud:control -- status URL`.
2. Корректно остановите локального бота. Скрипт импорта проверяет отсутствие блокировки работающего хранилища.
3. `npm run cloud:control -- import URL` сохраняет копию в `data/backups`, переносит состояние в отдельные строки SQLite и сверяет SHA-256 канонического снимка. Повторный импорт в заполненную базу запрещён.
4. `npm run cloud:control -- activate URL` включает обработчик.
5. `npm run cloud:control -- webhook URL` устанавливает секретный Telegram webhook с одним соединением и без удаления ожидающих сообщений.
6. `npm run cloud:control -- probe URL` отправляет администратору сообщение из облака. Проверьте реальное нажатие кнопки в боте.

После переключения локальный long polling не запускается. Экспорт: `npm run cloud:control -- export URL`. Резервные копии содержат личные ответы, остаются локально с правами 0600 и вне Git. Автоматического внешнего резервного копирования пока нет.

## Надёжность

- Webhook защищён WEBHOOK_SECRET; импорт, экспорт и управление — отдельным CLOUD_ADMIN_KEY.
- Публичный `/health` не раскрывает имена, роли или ответы.
- Сообщение сохраняется до подтверждения Telegram. Реестр update_id исключает двойную обработку; независимые сообщения могут поступать не по порядку.
- Состояние и отметка обработки фиксируются одной SQLite-транзакцией. Пустые настройки сохраняются.
- Очередь отправки переживает перезапуск. Durable alarms повторяют сетевые ошибки и выдерживают retry_after Telegram. Доставка at-least-once: при сбое между отправкой и фиксацией возможен дубль сообщения.
- После отзыва роли не доставляются ожидающие отчёты.
- PNG создаются WebAssembly resvg с Noto; sharp остаётся только в локальной версии. Telegram file_id кэшируется в SQLite.

## Квоты

Проверяйте фактический расход в Cloudflare. Бесплатный тариф имеет квоты запросов, времени исполнения, чтения/записи и хранения. 30 учеников — небольшая ожидаемая нагрузка, но не обещание неограниченной ёмкости. Проект не подключает платные AI-вызовы или тарифы. Документация: https://developers.cloudflare.com/workers/platform/limits/ и https://developers.cloudflare.com/durable-objects/platform/pricing/.

История пока загружается в память и клонируется обработчиком. При длительной эксплуатации потребуется архивирование старых попыток.
