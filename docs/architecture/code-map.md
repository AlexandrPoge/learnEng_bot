# Организация кода

Проект использует TypeScript с проверкой типов и неиспользуемых переменных.
`npm run check` проверяет и основной код, и все тесты. В `tests/tsconfig.json`
заданы те же строгие настройки; редактор также использует их для тестовых файлов.
Файл содержит не больше 150 строк, включая комментарии и пустые строки.
Ограничение действует также на учебные данные, скрипты и тесты.

## Telegram-бот

`apps/bot/src/handler.ts` — публичная точка входа для локального бота,
облачного обработчика и интеграционных тестов. Здесь только маршрутизация.

- `routing/` проверяет входящий update, вычисляет роли, нормализует команды
  и направляет сообщения или callback в нужный обработчик.
- `commands/` обрабатывает текстовые команды по областям: ученик,
  преподаватель, администратор, каталог и назначения.
- `callbacks/` обрабатывает кнопки по тем же областям. `true` означает,
  что действие обработано; `false` передаёт управление следующему маршруту.
  Обработчик старых ответов идёт последним.
- `catalog/` отвечает за учебник, уровни, школьные подборки и чтение.
- `practice/` запускает попытки, показывает вопросы и сохраняет ответы.
- `learning/` продолжает обучение и открывает приватный разбор снимка попытки.
- `homework.ts` строит единый список ученических ДЗ и следующее действие.
- `progress.ts` вычисляет прогресс ученика и строит историю с разбором.
- `classrooms/` отвечает за учебные группы, участников и выбранные темы.
- `assignments/` отвечает за шаблоны, получателей, сроки, подтверждение
  назначения и преподавательский просмотр сдачи.
- `editor/` разделяет создание черновика, правки полей и вопросов,
  историю и публикацию.
- `navigation/` содержит клавиатуры и оформление карточек.
- `ui/messages.ts` сохраняет исходящие сообщения в outbox, делит длинный
  текст и отключает старую навигацию при показе новой карточки.

Старые импорты `navigation.ts` и `editor.ts` сохранены как публичные входы.
Проверки роли и владельца выполняются при каждом действии, а не только
при отображении кнопки. Изменения состояния не вызывают Telegram API напрямую:
доставкой занимается отдельный обработчик очереди.

## Облако и хранилище

- `apps/cloud/src/worker.ts` проверяет секрет и направляет запрос в Durable Object.
- `learning-bot.ts` последовательно обрабатывает запросы и alarms.
- `processor.ts` применяет updates и доставляет outbox с повтором временных ошибок.
- `sql-store.ts` хранит состояние и реестр обработанных updates в SQLite.
- `environment.ts` описывает окружение, `http.ts` формирует ответы API.

Локальная версия использует `apps/bot/src/store.ts` с атомарной записью JSON.
Формат состояния при реорганизации не менялся.

## Общие правила и учебные данные

`packages/domain/` содержит оценивание, роли, время, дедлайны и статусы ДЗ.
Типы разделены в `types/` по областям; `types.ts` сохраняет публичные экспорты.

В `packages/content/` файлы курсов задают порядок тем. Содержимое темы находится
в одноимённом каталоге, в файле с её ID: например, `a1/to-be.ts`.
`supplements/` содержит дополнения к базовым объяснениям,
`presentation/` — вводные, `resources/` — внешние источники.
При переносе содержимое и порядок всех 106 тем сохранены.

## Изменения и проверки

- Давайте переменным и функциям имена по смыслу, не по позиции в массиве.
- Разделяйте код по ответственности, а не на произвольные пронумерованные части.
- Комментарий объясняет важное правило или причину, а не повторяет код.
- Не меняйте сериализуемые типы без проверки совместимости старого состояния.
- Большие тестовые наборы имеют файл запуска `*.test.ts`, отдельные сценарии
  в одноимённом каталоге и общий `helpers.ts`.
- В тестах эмулируются реальные Telegram updates через публичный обработчик.
  `tests/helpers/expectations.ts` проверяет наличие сообщений, клавиатур и других
  обязательных значений, одновременно сужая их типы без отключения строгих проверок.
  Облачные тесты используют Workers/SQLite runtime с подменой Telegram API.

Перед отправкой изменений:

```sh
npm run format
npm run quality
npm run build
npm test
npm run cloud:check
npm run cloud:test
```

Нужен Node.js 22+. `quality` проверяет форматирование, ограничение 150 строк
и TypeScript. Те же проверки выполняются в CI. Публикация выполняется отдельно.
