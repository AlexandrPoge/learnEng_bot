# Локальный этап

Node.js, ES modules, без runtime-зависимостей. Long polling использует официальный Telegram Bot API: https://core.telegram.org/bots/api.

- `apps/bot/src/main.mjs`: запуск, последовательная обработка updates, доставка сообщений.
- `handler.mjs`: команды, меню, роли по числовым ID, приглашения и прохождение.
- `store.mjs`: один JSON-файл, блокировка второго процесса, временный файл и atomic rename.
- `packages/domain`: сравнение ответов и отчёт.
- `packages/content`: проверенный ключ и теория Present Simple.

Ответы, следующий offset и исходящие сообщения сохраняются вместе до доставки. Повтор update не добавляет второй ответ. При перезапуске исходящие сообщения повторно доставляются. Доставка at-least-once: если Telegram принял сообщение, а процесс остановился до сохранения результата доставки, возможен дубль сообщения. Старые кнопки не меняют следующие ответы.

У попытки свой снимок урока и репетитора на момент старта. Репетитор видит только результаты связанных с ним попыток. Подключение требует одноразового кода с истечением через 24 часа; в интерфейсе заранее объясняется передача ответов. Полные отчёты включают исходные ответы. Время между стартом и отправкой не считается временем активной работы.

Хранилище рассчитано только на локальный прототип и один процесс. По мере роста файл целиком перечитывается/перезаписывается в памяти; нет заявленной ёмкости на тысячи учеников. Для публичного хостинга нужен адаптер постоянной БД, а не файл на временном диске. Миграции в `database` появятся на соответствующем этапе.

Сейчас доступна только практика с немедленной обратной связью. Контрольный тест со скрытым ключом, назначенные домашние задания и ручная проверка будут отдельными режимами.
