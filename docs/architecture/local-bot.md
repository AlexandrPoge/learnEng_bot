# Локальный этап

Node.js и TypeScript со строгой проверкой типов. `sharp` строит PNG из SVG-карточек правил. `tsc` собирает исходники в `dist`, `tsx` используется для тестов и локальных скриптов. Long polling использует официальный Telegram Bot API: https://core.telegram.org/bots/api. Веб-интерфейса нет.

- `apps/bot/src/main.ts`: запуск, последовательная обработка updates, доставка сообщений.
- `handler.ts`: команды, меню, роли по числовым ID, приглашения и прохождение.
- `store.ts`: один JSON-файл, блокировка второго процесса, временный файл и atomic rename.
- `packages/domain`: сравнение ответов и отчёт.
- `packages/content`: каталог из 66 тем A1–A2 и 330 упражнений. Каталог валидируется при импорте.

Ответы, следующий offset и исходящие сообщения сохраняются вместе до доставки. Повтор update не добавляет второй ответ. При перезапуске исходящие сообщения повторно доставляются. Доставка at-least-once: если Telegram принял сообщение, а процесс остановился до сохранения результата доставки, возможен дубль сообщения. Старые кнопки не меняют следующие ответы.

У попытки свой снимок урока и репетитора на момент старта. Репетитор видит только результаты связанных с ним попыток. Подключение требует одноразового кода с истечением через 24 часа; в интерфейсе заранее объясняется передача ответов. Полные отчёты включают исходные ответы. Время между стартом и отправкой не считается временем активной работы.

Хранилище рассчитано только на локальный прототип и один процесс. По мере роста файл целиком перечитывается/перезаписывается в памяти; нет заявленной ёмкости на тысячи учеников. Для публичного хостинга нужен адаптер постоянной БД, а не файл на временном диске. Миграции в `database` появятся на соответствующем этапе.

Доступны тренировка с немедленной обратной связью и проверочная с разбором после сдачи. Ручная проверка пока не реализована.

Навигация: `levels` → `l:УРОВЕНЬ:СТРАНИЦА` → `t:ID` → `p:ID`. На странице до пяти тем. Выбранная тема хранится у пользователя, активная попытка имеет приоритет: смена темы требует `/cancel`. `/lesson ID` и `/practice ID` позволяют открывать материалы без кнопок. Старые кнопки ответов проверяются по ID попытки и позиции вопроса.

`navigation.ts` формирует кнопки и карточки. `s:ID:rule|examples|traps:СТРАНИЦА` открывает раздел. Навигация ставит в очередь `editMessageReplyMarkup` для отключения старых кнопок и затем `sendMessage` для новой карточки внизу. Callback подтверждается подсказкой «Результат появится внизу чата». Это замена прежнего `editMessageText`, который мог незаметно менять сообщение выше в истории. Клиентская прокрутка через Bot API не настраивается.

`presentation.ts` добавляет значки, цели и простые вводные к 20 встроенным темам, а актуальный текст делит по маркерам «Примеры:», «Ловушки:» или «Ловушка:». Разделы разбиваются на небольшие страницы. Для старых уроков и пользовательских правок работает тот же разбор текста, без подмены на встроенное правило. `deeper-lessons.ts` расширяет встроенные темы и поднимает их версию до 2. `resources.ts` хранит проверенные внешние ссылки с типом, провайдером, датой и пояснением охвата.

`course-a1.ts`, `course-a2.ts` и `course-calendar-life.ts` добавляют ещё 46 тем. `course-builder.ts` создаёт типизированные уроки и словарные упражнения с допустимыми вариантами ответов. `types.ts` описывает уроки, вопросы, попытки, роли, Telegram updates и исходящие задачи.

`format.ts` строит текст с Telegram entities, не используя HTML. Разбиение сообщений учитывает UTF-16 и переносит смещения выделения в каждый фрагмент. Клавиатура прикрепляется только к последнему фрагменту. `g:УРОВЕНЬ:РАЗДЕЛ:СТРАНИЦА` фильтрует каталог, `/search` ищет тему без AI; навигация отменяет незавершённый поиск.

`learningMode` у пользователя принимает `child` или `adult`. По умолчанию показана простая подача. Режим влияет только на текст карточек. `review:ID:ПОЗИЦИЯ` проверяет владельца и завершённость попытки, затем показывает ответ по сохранённому снимку. Ролевые кнопки главного меню не заменяют проверку доступа на сервере.

`user.reading` хранит ID темы, раздел, страницу и версию. `/continue` сначала проверяет активную практику, иначе возобновляет чтение. Изменение версии сбрасывает страницу до нуля. `hint:ID:ПОЗИЦИЯ` проверяет текущую попытку и вопрос; использование подсказки фиксируется без добавления ответа. `repeat:ID` доступен только владельцу завершённой попытки: он создаёт отдельную попытку с неверно отвеченными вопросами исходного снимка, без assignmentId. Репетитор видит пометку повторения и количество использованных подсказок.

`ADMIN_IDS` задаётся только в окружении. Админ включает права репетитора, видит все результаты и назначает/отзывает репетиторов. Роли, выданные ботом, хранятся в `teacherIds`; `revokedTeacherIds` позволяет отозвать в том числе роль из `TEACHER_IDS`. Доступ к редактору и спискам проверяется при каждой команде. Отчёты в очереди помечены `requiredTeacher`: после отзыва роли они не отправляются.

`editor.ts` хранит черновик на редактора в `editors`. Опубликованные версии переопределяют встроенный каталог через `lessonOverrides`; прежние снимки сохраняются в `lessonHistory`. Публикация проверяет базовую версию и отклоняет конфликт двух редакторов. Восстановление создаёт новую версию, не переписывая историю. Библиотека общая для всех репетиторов на этом этапе.

Кнопки редактора используют `inputField`: следующее текстовое сообщение меняет выбранный раздел. Редактирование правила или всего текста удаляет прежние вводную и формулу, чтобы они не противоречили новым словам репетитора. Кнопки навигации сначала преобразуются в команды и не записываются как учебный материал. `teacherWelcome` хранит отложенное уведомление о выданной роли до первого `/start`.

`assignments` содержит получателя, автора, дедлайн с явным часовым поясом и снимок урока. Доступ к запуску проверяется по studentId; завершение привязывается к assignmentId. Повторно сдать закрытое задание нельзя. Отменённую попытку можно начать заново. Напоминаний по расписанию пока нет.

`classrooms.ts` обрабатывает классы, приглашения и назначение. `classes` хранит владельца, участников и ID тем. Коды класса многоразовые на 24 часа; вступление требует подтверждения и не меняет прежний `teacherId`. Проверки роли и владельца выполняются на каждом callback. Преподаватель видит своих участников, администратор — все классы. Ученики не видят списки или работы друг друга.

`homeworkTemplates` отделён от `lessonOverrides`: личные ДЗ не попадают в публичный каталог. Редактор хранит назначение черновика в `destination`. При публикации проверяются автор и версия. Назначение идёт через `user.workspace` с одноразовым nonce; подтверждение заново проверяет срок, роль и точный состав получателей. Создаются отдельные `Assignment` с общим `batchId`. При назначении классу администратором автором для отчётов остаётся владелец класса.

Попытка копирует `mode` из задания. В `test` нет кнопки подсказки, сервер отклоняет её поддельный callback, промежуточные сообщения не раскрывают правильность. Разбор доступен только после завершения. Это открытая учебная проверочная: чтение учебника не блокируется.

`timing.ts` сохраняет `lastActivityAt` и сумму `engagedMs`. Интервалы свыше пяти минут исключаются из оценки. Полное время считается отдельно по startedAt/completedAt. Старые попытки без событий не получают вымышленной оценки.

`rule-images.ts` экранирует текст в SVG, разбивает правило на страницы и создаёт PNG через sharp. В outbox сохраняется снимок урока и номер страницы. `delivery.ts` генерирует изображение при доставке и возвращает Telegram file_id для кэша `ruleImages`; ключ зависит от содержимого и версии рендерера. Негодный кэшированный file_id повторно загружается, ошибка рендера даёт текстовую навигацию. Бинарные изображения в JSON не сохраняются. `telegram.ts` поддерживает JSON и multipart FormData. Фотография репетитора хранится как `lesson.rulePhoto`, принимается только при ожидающем её черновике и действующей роли.
